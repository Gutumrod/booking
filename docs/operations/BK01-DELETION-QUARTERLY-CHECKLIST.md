## 2. Legal Hold Override — ตรวจต่อร้าน (บังคับทุกครั้ง)

ต่อร้านในเกณฑ์ ตรวจ **ก่อน** แตะข้อมูล:

- [ ] มีข้อพิพาท/ข้อร้องเรียนที่ยังไม่ยุติ?
- [ ] มีคิวอยู่ระหว่างคืนมัดจำ?
- [ ] มีการสอบสวนด้านความปลอดภัย?
- [ ] มีคำขอจากหน่วยงานรัฐ/กระบวนการทางกฎหมาย?
- [ ] รอบบัญชียังไม่ปิด?

**ถ้ามีข้อใด "ใช่" หรือ "ไม่แน่ใจ" ⇒ ตัดร้านนี้ออกจากรอบ (เก็บไว้) และจดเหตุผล — ห้ามถามซ้ำ ห้ามเดา**

- [ ] ร้านที่ถูก hold รอบนี้: `________________` เหตุผล: `________________`

## 3. Dry-run (บังคับ — ห้ามข้าม)

ต่อร้านที่ผ่าน §2:

- [ ] Dry-run ด้วยสคริปต์ที่มีอยู่จริงเท่านั้น: `scripts/cleanup-stale-deposit-slips.mjs`
      (dry-run เป็นค่าเริ่มต้น · **ไม่ลบสลิปที่ผูกกับ booking ทุกกรณี** · ต้องระบุ `--min-age-hours` ทุกครั้ง)
- [ ] `--min-age-hours` มาจาก A-27 ข้อ 3 (12 เดือน ≈ `8760`) — **operator พิมพ์ค่าทุกครั้ง ไม่มี default**
- [ ] ดูรายการ `deletable` / `kept` และเหตุผลของแต่ละรายการ
- [ ] **ตรวจว่าไม่มีรายการที่เป็น booking ที่มีเหตุการณ์เงินอยู่ในกอง `deletable`** (ถ้ามี ⇒ หยุด, ไป §4)
- [ ] บันทึกผล dry-run (วันที่ + จำนวน deletable/kept + sha256 ของแผน ถ้ามี): `______________`

> ตัวอย่างเชิงข้อความ (ห้ามรันบน production โดยไม่ผ่าน scope ที่รีวิว):
> `node scripts/cleanup-stale-deposit-slips.mjs --shop <shopId> --min-age-hours 8760`

## 4. booking ที่มีเหตุการณ์เงิน — ห้าม DELETE

ต่อทุกร้าน:

- [ ] ยืนยันว่าเครื่องมือ/แผน **ไม่แตะ** `deposit_money_events` (ไม่ลบรายแถว)
- [ ] ยืนยันว่า **ไม่มี** `DELETE` กับ `bookings`/`shops` ที่มีเหตุการณ์เงินผูกอยู่ (FK ไม่ cascade + trigger ห้ามแก้)
- [ ] ถ้างานต้องจัดการ booking ประเภทนี้ ⇒ **ระงับ + ส่งต่อ** (anonymize ยังไม่มีในระบบ — B1)
- [ ] ไม่แก้/ปิด trigger หรือ FK เพื่อให้ลบผ่าน

**กฎเต็ม:** `BK01-DATA-DELETION-RUNBOOK.md` §3

## 8. บันทึกความไม่แน่ใจ

- เกณฑ์ 12 เดือน/วันอ้างอิง คัดจาก A-27 (Owner "ตามนี้" 2026-10-02) — **ยังไม่ผ่านทนาย/บัญชี** และห้ามประกาศต่อลูกค้าก่อนยืนยัน
- Checklist นี้ **ไม่ใช่สคริปต์** — ทุกคำสั่งที่อ้างเป็นตัวอย่างเชิงข้อความ ต้องรันโดย operator ที่มีสิทธิ์ ผ่าน dry-run และคนที่สองเสมอ
- `--min-age-hours` = 12 เดือนของ**รูปสลิป** (A-27 ข้อ 3) ซึ่งเป็นข้อที่ต้องให้ทนาย/บัญชียืนยันก่อนใช้กับข้อมูลจริง
