# Lane B WU-1 / WU-2 embedded source proof

From this directory: `npm ci --ignore-scripts` then `npm run proof`.
From the repository root: `node scripts/proofs/lane-b/wu1_e2e.mjs` after the dependency install.
The optional first argument selects a different repository checkout. Default repo is resolved relative to this harness, independent of cwd.

PGlite 0.5.8 is pinned in this isolated package and lockfile; it is not a runtime dependency of either app. The harness runs the frozen 30-migration chain, `20260926120000_bk01_entitlement_packs.sql`, `20260927120000_bk01_runtime_route_rpcs.sql`, `20260927130000_bk01_trial_line_bind.sql`, the House Storage SQL fixture, `20260928120000_bk01_house_upload_grants.sql`, and generated bootstrap in embedded Postgres, with synthetic Auth/managed-schema fixtures, one pgcrypto digest stub, and substitutions for unsupported extension/GiST statements. The checked-in House SQL fixture is copied from `saas-product-hub/docs/platform/shared-runtime/storage/house_storage_upload_grants.sql`; verify its SHA-256 against the same file on the House branch before using the proof. The harness records that fixture hash in `WU2-PGLITE-PROOF.json`. It writes proof output under `BK01_PROOF_OUTPUT_DIR` when set, or `supabase/shared-runtime/` by default. Set output variables to absolute paths outside the checkout so evidence is not committed:

```powershell
$env:BK01_PROOF_OUTPUT_DIR = 'D:\AI-Workspace\runtime\relay\house-20260928\live-window-last-mile\booking\proofs'
$env:BK01_BASELINE_CATALOG_OUTPUT = 'D:\AI-Workspace\runtime\relay\house-20260928\live-window-last-mile\booking\baseline-catalog.json'
npm run proof
```

`BK01_BASELINE_CATALOG_OUTPUT` is optional and records a schema/grant/function/policy snapshot without row data. Both paths above are safe local examples; neither variable contains a credential. At the WU-2 checkpoint, the runtime set was eleven explicit RPCs plus eight signature-exact PUBLIC legacy exceptions. Group67 adds only `claim_due_shop_email_notifications(integer)`, so the current contract is twelve explicit RPCs plus those same eight exceptions; a 13th explicit grant and a 9th PUBLIC exception fail the guard. The SQL checks cover upload grant issuance through BK01, matching House registration, exact Storage consume, replay denial, expiry and MIME/size binding, runtime-role/product/bucket isolation, and guarded compensating rollback alongside the existing suite. This is source-level evidence, not hosted Supabase or Lane B criteria completion. PGlite cannot prove hosted Auth hook issuance, PostgREST exposed-schema filtering, Supabase managed PUBLIC ACL behavior, real pgcrypto strength, signed upload URL authorization, or real Storage enforcement. See the comments in the harness for all substitutions.

No LAB, external DB or credentials are used. The harness also keeps the older WU1 identity proof. The existing WU2 section contains 31 SQL-level checks. The A2 runner-through addition contributes five gates: inclusive 1–3 selection, atomic first interval, migration-4-only second interval after House SQL, final catalog/data/ledger snapshot equivalence with a one-shot four-migration apply, and rollback of both DDL and ledger on interval failure. Snapshot comparison excludes only `created_at` and `updated_at`, whose `now()` values necessarily differ across transaction schedules. The combined proof reports 42 checks.
