# Lane B WU-1 / WU-2 embedded source proof

From this directory: `npm ci --ignore-scripts` then `npm run proof`.
From the repository root: `node scripts/proofs/lane-b/wu1_e2e.mjs` after the dependency install.
The optional first argument selects a different repository checkout. Default repo is resolved relative to this harness, independent of cwd.

PGlite 0.5.8 is pinned in this isolated package and lockfile; it is not a runtime dependency of either app. The harness runs the frozen 30-migration chain, `20260926120000_bk01_entitlement_packs.sql`, `20260927120000_bk01_runtime_route_rpcs.sql`, and generated bootstrap in embedded Postgres, with synthetic Auth/managed-schema fixtures, one pgcrypto digest stub, and substitutions for unsupported extension/GiST statements. It writes `WU2-PGLITE-PROOF.json` under `BK01_PROOF_OUTPUT_DIR` when set, or `supabase/shared-runtime/` by default. The effective `bk01_runtime` EXECUTE set is exactly ten explicit RPCs plus eight signature-exact PUBLIC legacy exceptions accepted by the caretaker on 2026-09-27; an 11th explicit grant and a 9th PUBLIC exception fail the guard. The SQL-level checks cover LINE inbound event replay/lease, Stripe same-event state replay/finalization, notification attempt scoping, upload grant issuance metadata, and direct table/cross-product denial. This is source-level evidence, not hosted Supabase or Lane B criteria completion. The upload check proves grant issuance, path derivation, MIME/size and expiry metadata only; one-time consumption/replay denial requires the separate House Storage artifact and LAB live window. PGlite cannot prove hosted Auth hook issuance, PostgREST exposed-schema filtering, Supabase managed PUBLIC ACL behavior, real pgcrypto strength, or real Storage enforcement. See the comments in the harness for all substitutions.

No LAB, external DB or credentials are used. The harness also keeps the older WU1 identity proof. This WU2 run has 31 SQL-level checks. Re-run source verifier and tests after regenerating bootstrap.
